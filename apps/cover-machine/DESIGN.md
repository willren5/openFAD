# openFAD Cover Machine Design

## 产品意图

openFAD Cover Machine 是中文优先、单文件优先的封面制作工具。它让轻度用户在浏览器里快速生成发行封面，也让深度用户能审查尺寸、透明图层、项目 JSON、导出证据和 public-safe 边界。

产品气质：安静、可靠、像设计工具，不像营销落地页。

## 用户轨道

轻度用户：

- 打开 `index.html`。
- 点击“打开示例”。
- 修改标题、艺人、发行信息。
- 选择导出目标。
- 点击导出。

深度用户：

- 展开专业设置。
- 调整画布、裁切、字体、图层、透明输出和导出目标。
- 保存或导入项目 JSON。
- 检查导出状态、文件名、尺寸、大小和重试状态。
- 跑 `npm run test:cover` 验证静态合同和浏览器行为。

## 信息架构

首屏必须包含：

- 产品名和中文一句话定位。
- “打开示例”主按钮。
- 导出目标选择。
- 导出按钮和导出状态。
- 画布预览。
- 基础文字输入：标题、艺人、发行信息。

专业区包含：

- 画布尺寸和平台目标。
- 背景图上传、裁切、缩放、对齐。
- Logo / 透明图层上传。
- 字体选择和字号。
- 文本位置、颜色、阴影、描边。
- 项目 JSON 保存/载入。
- 使用分析开关。

## 组件合同

导出目标：

- `dsp-3000`：发行封面，方形 JPG。
- `social-square`：社媒方形图。
- `transparent-layer`：透明 PNG 图层。
- 新增目标必须声明尺寸、格式、背景规则、透明规则和文件名后缀。

项目 JSON：

- 必须包含 openFAD verification metadata。
- 不得包含本机绝对路径。
- 不得内嵌真实私有资产。
- 导入失败必须回滚，不得半更新 UI。

示例素材：

- 只能使用公开安全占位图。
- 默认 Logo 文案使用 `openFAD`。
- 默认日志前缀使用 `[openFAD]`。
- 不得用 `[FAD]`、`FAD Records Release` 或真实发行名当默认值。

使用分析：

- 默认关闭。
- 只允许发送匿名使用事件。
- 不上传封面图片、项目 JSON、导出文件、文件名、路径、账号或任何私有素材。

## 失败路径

必须有中文可操作说明：

- 浏览器不支持当前导出：提示换 Chrome / Edge。
- 下载未出现：提供“重试下载”。
- 图片太大或解码失败：提示压缩图片或换本地文件。
- 远程图片跨域：提示上传本地图片。
- 项目 JSON 损坏：说明未应用任何变更。
- 自动保存失败：保留当前编辑状态，提示手动导出项目 JSON。

失败文案格式：

```text
发生了什么：下一步动作 / English technical fallback
```

示例：

```text
导出未完成：请点击“重试下载”，或换用 Chrome / Edge。
```

## 可访问性

- 所有输入、按钮、开关都有可见中文 label。
- 图标按钮必须有 `aria-label`。
- 导出状态使用 `role="status"` 或等价 live region。
- 键盘可以完成打开示例、编辑文字、导出、重试下载。
- 焦点样式可见。
- 文字不能因为长文件名或错误消息横向溢出。

## 性能

- 首屏不请求外部资源。
- 默认示例素材必须小。
- 用户上传大图时先做边界检查，再创建大 canvas。
- 导出过程不能让状态栏失去响应。
- 保存失败不能阻塞继续编辑。

## 验收命令

```bash
npm run scan:public
npm run test:cover
git diff --check -- .
```

发布前还要跑根级：

```bash
npm test
npm run package:web
npm run checksums
npm run release:manifest
```

## 交付清单

每次 Cover 改动必须回答：

- 轻度用户 30 秒路径是否仍然成立？
- 深度用户是否还能保存/导入项目 JSON？
- 导出失败是否有下一步动作？
- 默认 UI 是否只使用 openFAD public-safe identity？
- `npm run test:cover` 是否 fresh pass？
